# 🛠️ Инструменты

> 💡 **Есть путь короче.** Всё, что делают первые два скрипта, умеет
> [расширение](../extension/README.md) — прямо на сайте и без ручных шагов.
> Эти инструменты остаются для разбора пачкой и для случаев, когда расширение не поставлено.

| Файл | Где запускать | Зачем |
|---|---|---|
| [grab-console.js](grab-console.js) | **в консоли браузера** (F12 → Console) | забрать модалки со ставками |
| [parse-bets.ts](parse-bets.ts) | `bun run parse` | разобрать их в отчёт |
| [scan-secrets.ts](scan-secrets.ts) | сам, как git-хук | не пустить чувствительное в публичный репозиторий |

Вся математика вынесена в [`extension/src/engine.ts`](../extension/src/engine.ts) и общая
с расширением, поэтому формулы в «подсказке на сайте» и в «отчёте в репозитории»
не могут разойтись. Скрипты — это только ввод-вывод вокруг неё.

Импортируется она как `@lp/extension/engine` — это workspace-зависимость, объявленная
в [package.json](package.json). Запускать скрипты нужно **из корня** репозитория
(`bun run parse`, `bun run scan`): `parse-bets.ts` читает `input/` относительно текущей
папки. А вот свои конфиги — [`.scanignore`](.scanignore) и `.scanlocal` — сканер ищет
рядом с собой, так что на них место запуска не влияет.

> ⚠️ **Они работают в разных местах.** В консоль браузера идёт только `grab-console.js`.
> Если вставить туда `parse-bets.ts`, браузер ответит
> `Cannot use import statement outside a module` — это скрипт для терминала.

## Порядок работы

### 1. Один раз за сессию — вставить сборщик

Открой сайт → `F12` → вкладка **Console** → вставь **всё содержимое** [grab-console.js](grab-console.js) → Enter.

Должно появиться: `LP  Готово. LP.grab() на каждом матче → LP.save() в конце.`

Если консоль ругается на вставку (`allow pasting`) — набери в ней `allow pasting`, нажми Enter и вставь снова.

### 2. На каждом матче

Открой модалку ставок → в консоли:

```js
await LP.grab()
```

Сборщик **сам кликнет обе вкладки команд** и заберёт оба состояния. Ответ вида
`Magic vs Ninjas in Pyjamas [StarLadder BO3] — заходов 2/2, всего в буфере 2`.

Закрой модалку, открой следующий матч, снова `await LP.grab()`. Накопленное живёт
в `localStorage`, вкладку можно перезагружать.

### 3. В конце — выгрузить

```js
LP.save()
```

Скачается `bets-<дата>.json`. Положи его в **`input/html/`**.

**Буфер чистится сам:** после `LP.save()` localStorage очищается — файл уже на диске,
вторая копия не нужна. Нужно оставить — `LP.save({ keep: true })`.

### Гигиена буфера

| Команда | Что делает |
|---|---|
| `LP.count()` | таблица: что накоплено, когда собрано, сколько весит |
| `LP.drop('3DMAX')` | выбросить записи, чей заголовок содержит подстроку |
| `LP.drop('не найдены')` | выбросить неудачные заходы без имён команд |
| `LP.clear()` | снести всё |

Повторный `LP.grab()` на том же матче **не плодит дубль, а обновляет запись** — кэфы
шевелятся, и свежий заход должен вытеснять старый. Ключ — «матч + сторона».

⚠️ **Не смешивай сессии.** Если часть матчей собрана час назад, а часть только что —
кэфы в них из разных моментов, и сравнивать их между собой некорректно. Перед новым
обходом лучше `LP.clear()`.

### 4. Разобрать

```bash
bun run parse
```

Читает всё из `input/html/` (и `.json`, и `.html`), пишет в `input/parsed/`:
- **`report.md`** — читаемый отчёт, его я и смотрю
- `report.json` — то же машинно

Явные пути тоже работают: `bun run parse .dev/ --out input/parsed`

## Что считает парсер

Помимо вытаскивания всех кэфов:

**Сетка исходов серии.** Разворачивает четыре исхода BO3 (2:0, 2:1, 1:2, 0:2).

Считается в два шага, и это важно. Сначала берутся три события, которые **полностью
покрывают пространство**: «A всухую», «B всухую», «три карты». Они живут в разных книгах,
поэтому маржа снимается **совместной нормировкой**, а не попарно — попарное снятие
не даёт в сумме единицу. Потом «три карты» делятся между командами по исходу серии.

**Сколько заходов реально нужно**

| Что считаем | Хватит одного захода? |
|---|---|
| Исход серии | ✅ да — реконструкция даёт ~0.5 п.п. точности |
| Тотал карт | ✅ да — рынок общий для обеих вкладок |
| **Фора по картам** | ❌ **нет** — оценка разгрома соперника будет занижена |
| Карта #1, форы по раундам, пистолеты соперника | ❌ нет |

Реконструкция соперника по исходу проверена на magic vs NiP: выведенный кэф **2.006**
против реального **2.028**. А вот P(magic 2:0) при одном заходе выходит **18.2%** против
честных **25.5%** с двух — потому что «A +1.5» несёт свою маржу, и вычитание её не убирает.
Поэтому `LP.grab()` и ходит по обеим вкладкам.

**Сверка рынков.** P(три карты) считается двумя независимыми путями — через форы по картам
и через тотал карт. Расхождение от 5 п.п. отчёт помечает 🚨 как кандидата в мягкое место линии.
Порог именно такой, потому что у книг разная маржа (форы ~10%, тотал карт ~8.4%), и пара
процентов расхождения — её нормальное следствие, а не ошибка букмекера.

## 🛡️ Страж коммитов

Репозиторий публичный, а рядом с ним постоянно лежат выгрузки чужого сайта. Одного
`git add -A` в невнимательный момент достаточно, чтобы опубликовать чужие никнеймы.
Поэтому проверка стоит на pre-commit, а не на самодисциплине.

### Установка

```bash
bun run hook:install
```

Прописывает `core.hooksPath = .githooks`. Хук **версионируется** — в отличие от
`.git/hooks/`, который живёт только на одной машине и теряется при клонировании.

### Использование

```bash
bun run scan          # что уйдёт в коммит (то же, что делает хук)
bun run scan:all    # аудит всех отслеживаемых файлов
```

Проверяется **содержимое индекса** (`git show :файл`), а не рабочая копия. Это принципиально:
после `git add -p` в коммит уходит не то, что видно в редакторе.

### Что ловит

| Категория | Примеры | Уровень |
|---|---|:-:|
| Ключи и токены | приватные ключи, JWT, AWS, GitHub, Slack, Stripe, Google, Anthropic, OpenAI, Telegram | 🚫 блок |
| Секреты в коде | `api_key = "…"`, строки подключения с паролем | 🚫 блок |
| Сессии | `PHPSESSID`, `Set-Cookie`, `remember_token` | 🚫 блок |
| **Чужие персданные** | никнеймы из чата сайта, ссылки на профили | 🚫 блок |
| **Сырые выгрузки** | HTML-дампы линии букмекера | 🚫 блок |
| Локальное окружение | `C:\Users\<имя>`, домашние пути | 🚫 блок |
| Мягкие сигналы | почта, разметка логина, файлы больше 512 КБ | ⚠️ предупреждение |

Найденное **маскируется в выводе**: `eyJhbGci••••••ryP4J…`. Иначе секрет осел бы
в истории терминала и в логах CI — то есть проверка сама стала бы утечкой.

### Почему проектных паттернов нет в самом сканере

Сканер публичный. Вписать в него домен букмекера значит **опубликовать то, что он охраняет** —
проверка защищала бы от утечки, будучи утечкой.

Поэтому такие правила лежат в **`tools/.scanlocal`**, который в `.gitignore`. Формат — по
регулярке на строку:

```
имя-сайта-без-зоны      # Домен букмекера
data-to="\d{6,}"        # ID пользователей из чата
```

При клонировании на новую машину этот файл придётся создать заново — так и задумано.

> 🎯 **Страж поймал это прямо при написании документации.** В первом варианте примера
> выше стоял настоящий домен — и `--all` заблокировал коммит на `tools/README.md:171`.
> То есть документация к защите от утечки сама оказалась утечкой, и её остановил
> тот самый механизм, который она описывает. Лучшего теста придумать было нельзя.

### Ignore-механика, три уровня

От самого точечного к самому грубому:

| Уровень | Как | Когда |
|---|---|---|
| **Строка** | дописать в неё комментарий `scan:ignore` | безопасен один пример в доке |
| **Файл** | `scan:ignore-file` в первых 2000 символах | весь файл — заведомо безопасный образец |
| **Путь** | добавить glob в [`.scanignore`](.scanignore) | целая папка вне проверки |

Точечный уровень предпочтительнее: исключение видно прямо в коде, а не спрятано
в отдельном файле, куда никто не заглядывает.

Отдельно есть **пороги срабатывания**. Правило «сырой дамп линии» требует **5+ вхождений**
`class="koef"`, поэтому пара примеров разметки в этой самой документации его не будит,
а настоящая выгрузка (там 28+ коэффициентов) — будит. Это лучше, чем глушить весь файл.

### Обход

```bash
git commit --no-verify
```

Работает всегда — хуки не защита от себя самого, а страховка от невнимательности.
Если приходится обходить регулярно, значит правило настроено плохо: чините правило, а не привычку.

## ⚠️ Ловушка разметки, на которой легко обжечься

`data-type="fora"` и `data-type="fora2"` — это **не «минус» и «плюс»**. Это две разные
двусторонние книги, а знак форы зависит от того, чья вкладка открыта:

| Вкладка | data-type | Что написано на сайте | Кэф |
|---|---|---|---|
| NiP | `fora_2` | NiP **−1.5** | 2.684 |
| NiP | `fora2_2` | NiP **+1.5** | 1.248 |
| magic | `fora_1` | magic **+1.5** | 1.377 |
| magic | `fora2_1` | magic **−1.5** | 3.285 |

То есть `fora_N` = «ставка за команду N в книге fora», и на разных вкладках это разный знак.
Парсер поэтому берёт знак **из подписи** `<b>Команда</b><i>±X</i>`, а конвенцию `data-type`
держит лишь как запасной вариант. То же самое с `rounddif` / `rounddif2`.

Проверка, что чтение верное: пары складываются в осмысленную маржу — книга `fora` даёт 9.9%,
книга `fora2` — 10.6%. При неправильном чтении знака получались бы отрицательные маржи.

**Маржа по каждому двустороннему рынку** + подсветка: 🟢 <8.8% · 🟠 <9.5% · 🔴 выше.

**Колонка «Нужна P для Edge ≥3%»** — минимальная вероятность, при которой ставка проходит
порог входа из [README.md](../README.md). Смотрю на неё и сразу вижу, дотягивает ли моя оценка.

**Тиры рынков** 🅰️/🅱️/🅾️ — из [MARKETS.md](../MARKETS.md), чтобы ловушки не мозолили глаза.
