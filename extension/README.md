# 🧩 Расширение: расчёт линии на месте

Считает честные вероятности, маржу книг и порог входа **прямо в модалке ставок** —
без скриншотов, выгрузок и ручного запуска парсера.

Ни одного обращения к сети и ни одного запроса к ИИ: вся арифметика локальная и мгновенная.
Модель нужна только там, где нужна оценка вероятности, — для этого есть кнопка брифа.

---

## Установка

```bash
bun install
cp extension/manifest.example.json extension/manifest.json   # подставить домен сайта
bun run build
```

Затем загрузить распакованное расширение из папки `extension/dist`:

| Браузер | Адрес страницы расширений |
|---|---|
| Chrome, Edge, Brave, Opera | `chrome://extensions` |
| **Яндекс Браузер** | **`browser://extensions`** |

Дальше везде одинаково: включить **режим разработчика** (тумблер справа сверху) →
**Загрузить распакованное расширение** → выбрать `extension/dist`.

### Про Яндекс Браузер

Он на Chromium, поэтому расширение работает как есть. Два момента:

**Боковой панели может не быть.** `chrome.sidePanel` — это API Chrome 114+, и в Яндексе
его может не оказаться. Код это проверяет и при отсутствии открывает панель
**отдельным окном** — вся функциональность та же, просто окно не прилипает к краю.
Повторный клик по иконке выводит уже открытое окно вперёд, а не плодит копии.

**Возможны предупреждения о манифесте.** Если браузер ругается на неизвестные ключи —
удали из `manifest.json` строки `"sidePanel"` в `permissions` и весь блок `"side_panel"`.
Запасной путь через окно продолжит работать.

> ⚠️ **Про манифест.** Рабочий `manifest.json` содержит домен сайта и потому
> **не версионируется** — страж коммитов его заблокирует, и правильно сделает.
> В репозитории лежит `manifest.example.json` с плейсхолдером. Та же логика, что с `.scanlocal`.

Разработка: `bun run dev` — пересборка по изменениям. Расширение после неё надо перезагрузить
в `chrome://extensions` (для content script горячей замены не бывает).

## Что видно

### ⚠️ Про снятие второй стороны

Автоматическое переключение вкладок команд **выключено по умолчанию**, и это не осторожность
ради осторожности: каждое переключение — запрос к сайту, и в первой версии оно приводило
к блокировке за спам (см. разбор ниже).

Вторая сторона снимается **по кнопке «Обе стороны»** и **не чаще одного раза на матч**.
Нужна она только для точной оценки разгрома: исход и тотал карт считаются и по одной стороне.

### Рядом с модалкой — панель расчёта

Прилипает **сбоку** от окна ставок: шансы обеих команд, сетка исходов, пороги входа
по каждому рынку, маржа по книгам и предупреждения. Сворачивается кнопкой в шапке.

Панель живёт в `position: fixed` и лежит в `body`, а не внутри модалки. Это не косметика:
первая версия вставлялась внутрь сверху и **выталкивала содержимое модалки вниз**, из-за чего
та прыгала при каждом пересчёте. Фиксированное позиционирование выводит панель из потока —
на вёрстку сайта она не влияет вообще. За движением модалки панель следит опросом
`getBoundingClientRect` раз в 300 мс: сайт двигает её инлайновыми стилями, и ловить это
событиями ненадёжно.

### Бейджи у коэффициентов

Рядом с каждым кэфом появляется бейдж вида **`≥52%`**. Это не implied — в implied сидит
маржа букмекера. Это **минимальная вероятность, при которой ставка проходит порог входа**,
единственное число, с которым осмысленно сравнивать свою оценку: «я правда думаю,
что тут больше 52%?» — да или нет.

Маржа-ловушки (чёт/нечёт, пистолеты, «первыми N раундов») помечаются зачёркнутым **`пас`**:
считать для них Edge — значит делать вид, что там есть что считать.

### В боковой панели — разбор

Сетка исходов, маржа по каждой книге, сверка книг между собой и **калькулятор Edge**:
вписываешь свою вероятность — сразу видишь Edge и размер ставки по шкале из [README](../README.md).

## Архитектура и почему она такая

```
extension/
├── manifest.example.json    в репозитории, с плейсхолдером домена
├── manifest.json            локальный, в .gitignore
├── build.ts                 Bun.build: iife для content, esm для панели
└── src/
    ├── engine.ts            ← вся математика, общая с tools/parse-bets.ts
    ├── engine.test.ts       20 тестов на реальных фикстурах
    ├── __fixtures__/        три формы линии, встреченные в живых данных
    ├── lib/                 modal (поиск и снятие), brief, chrome-storage, utils
    ├── store/               zustand поверх chrome.storage
    ├── content/             оверлей: Shadow DOM, без Radix
    └── panel/               боковая панель: React + shadcn на Base UI
```

### Один движок на два входа

`engine.ts` не знает ни про DOM, ни про файлы — только чистые функции над строкой HTML.
Расширение отдаёт ему `root.outerHTML`, скрипт — содержимое файла. **Формулы физически
не могут разойтись** между подсказкой на сайте и отчётом в репозитории.

### Почему content script в iife

Content script в MV3 **не может быть ES-модулем** — браузер его просто не выполнит.
Поэтому `format: 'iife'` в сборке, тогда как панель и service worker живут в нормальных
контекстах и собираются в `esm`.

### Почему оверлей без компонентной библиотеки

Оверлей живёт в Shadow DOM — иначе CSS букмекера ломал бы вёрстку, а preflight Tailwind
ломал бы страницу букмекера. Изоляция нужна в обе стороны.

Но компоненты с порталами (выпадающие списки, диалоги, тултипы) по умолчанию рендерятся
в `document.body`, то есть **вылезают из Shadow DOM и теряют стили**. Base UI это решает —
у него `container` принимает `ShadowRoot` прямо в типе, в отличие от Radix, где там только
`HTMLElement`. Проброс сделан один раз в [`ui/index.tsx`](src/panel/ui/index.tsx) через
`ShadowRootContext`, а не при каждом использовании — это и есть смысл модели shadcn,
где код компонентов лежит в проекте.

При этом в самом оверлее всплывашек пока нет: там бейджи и строка сводки, компонентной
библиотеке нечего делать. Провайдер написан заранее, чтобы дверь осталась открытой.

### Почему стор на chrome.storage, а не localStorage

Content script и боковая панель — **разные JS-реальности**, `localStorage` у них разный.
`chrome.storage` общий для всех контекстов, и именно это делает возможным мост
«оверлей посчитал → панель показала».

Отдельно нужна подписка на `chrome.storage.onChanged`: у каждого контекста свой экземпляр
стора, и без синхронизации они разъедутся — поменял юнит в панели, а оверлей считает
по-старому. Защита от самозацикливания — в [`lib/chrome-storage.ts`](src/lib/chrome-storage.ts).

### Две ошибки первой версии — и что из них следует

Обе всплыли при первом же запуске в живом браузере, и обе поучительные.

**1. Петля обратной связи → блокировка сайтом.** Наблюдателей за DOM было два, и оба
реагировали на клик по вкладке команды, который делали **мы сами**. Получилось
«клик → мутация → съём → клик», сайт увидел спам запросами и заблокировал.

Исправлено тремя правилами в [`content/index.tsx`](src/content/index.tsx):
- флаг `capturing` — пока идёт съём, любые мутации считаются нашими и игнорируются;
- обрабатывается только отпечаток линии, который ещё не обрабатывали;
- вторая сторона снимается максимум один раз на матч, и только по кнопке.

Наблюдатель [`observeDom`](src/lib/modal.ts) намеренно **не хранит своего состояния**:
решать, чьи это мутации, должен вызывающий, потому что только он знает про свои клики.

**2. Оверлей без стилей.** Причина оказалась не в сборке, а в одной строке CSS:
переменные темы были объявлены в `:root`, а **внутри Shadow DOM `:root` не совпадает
ни с чем** — этот селектор матчит только корень документа. Все цвета оставались
неопределёнными, и блок рендерился чёрным текстом без фона.

Нужен `:root, :host` — именно так Tailwind кладёт и свою тему. Заодно стили перестали
тянуться через `fetch`: теперь они вшиваются в бандл строкой на этапе сборки, потому что
строка не может «не долететь» — ни сети, ни CSP, ни асинхронности.

**3. Расширение отравляло собственный вход.** Бейджи вставляются в DOM рядом с коэффициентами,
а потом этот же DOM читается обратно. Парсер привязывает ставку к ближайшему свободному
`.koef` **по расстоянию в тексте**, и лишние узлы это расстояние меняли — привязка съезжала
на одну позицию. В брифе это вылезло как книга «чёт/нечёт» с кэфом овертайма внутри
и маржой **−31.4%**, которую отчёт бодро объявил «самым дешёвым рынком».

Две правки: перед разбором модалка клонируется и из клона удаляются `.lp-badge` и хост
оверлея; плюс книга с маржой вне диапазона 1–25% помечается 🚨 и исключается из поиска
самого дешёвого рынка. Отрицательная маржа означала бы вилку внутри одного букмекера —
такого не бывает, и подавать это как находку нельзя.

### Почему второй заход по вкладкам

Модалка показывает кэфы только одной команды. Исход и тотал карт восстанавливаются и
по одной стороне, а вот **вероятность разгрома — нет**: она выводится из «+1.5», где своя
маржа, и вычитанием та не убирается. На реальных данных разница **18.9% против 25.2%**.
Поэтому расширение само переключает вкладку, снимает вторую сторону и возвращает как было.

## Чего здесь намеренно нет

**React Query и axios.** В расширении нет ни одного сетевого запроса: распарсили DOM,
посчитали, положили в стор. React Query решает кеширование и ретраи серверных запросов,
а сервера нет.

Когда дело дойдёт до запросов, стоит помнить: из content script они упрутся в CORS и
должны идти через service worker, а в MV3 у service worker **нет `XMLHttpRequest`** —
значит голый `fetch`, а не библиотеки, рассчитывающие на XHR.
